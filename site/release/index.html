@ghostpaw/souls 0.3.0

Change your agent's prompt when the evidence agrees.

souls keeps an agent's identity as a short essence plus traits, and every trait carries the evidence that earned it. Observations pile up as shards, the soul is ready for a change only when they come from two independent sources over at least a day, and every level-up can be reverted.

Free and MIT licensed for Node.js 24 or newer, with zero runtime dependencies. The MCP server keeps identity and evidence in ~/.ghostpaw/souls.db on your machine.

The gate rules come from the library: at least two independent sources and at least a day between the oldest and newest pending shard.

All four shards are still pending after the level-up. Using them up is a separate decision your code makes.

What a soul is made of

A soul is one identity, and it is not a prompt template.

Essence
A few sentences in the first person about how the agent thinks and judges.
Trait
One principle with its provenance, the evidence that it was earned.
Shard
One observation from any source, attributed to one or more souls. Shards pile up quietly until the gate opens.
Level-up
Merge overlapping traits, promote absorbed ones into the essence, carry the rest. The level goes up by one, and revertLevelUp goes back.
Rendered block
renderSoul prints essence and active traits as markdown for your system prompt. It only changes when the soul does.
Mentor
One built-in soul, tuned to guide the refinement steps. soul.renderSoulsSoulPromptFoundation() returns it.

Seven tools for agents: search_souls, review_souls, inspect_souls_item, observe_soul, refine_soul, level_up_soul and manage_soul.

If a prompt that edits itself worries you

People have watched agents that rewrite their own instructions do strange things, and deleting SOUL.md just sends an agent back to its default. Both are reasonable things to worry about.

  • souls does not call a model. Your code or your agent proposes a change, and souls checks it and keeps the history.
  • A level-up that drops an active trait is refused before anything is written.
  • Every level-up can be reverted, and every trait keeps its provenance.
  • The identity and its full history sit in SQLite next to your other data, so going back means a call, not a restore from backup.
  • Node.js 24 or newer, because it uses the built-in node:sqlite.

Start from the README

import { DatabaseSync } from 'node:sqlite';
import { initSoulsTables, read, write } from '@ghostpaw/souls';

const db = new DatabaseSync(':memory:');
initSoulsTables(db);

const soul = write.createSoul(db, {
  name: 'Reviewer',
  essence: 'I review code by reading for intent before scanning for bugs.',
  description: 'Code review specialist',
});

write.addTrait(db, soul.id, {
  principle: 'Read the PR description before the diff.',
  provenance: 'Reviews that started with code missed architectural intent 3 of 4 times.',
});

write.dropShard(db, {
  content: 'Reviewer caught a naming inconsistency by reading the RFC first.',
  source: 'session',
  soulIds: [soul.id],
});

const rendered = read.renderSoul(db, soul.id);

To run it as an MCP server, add npx -y @ghostpaw/souls mcp to your client. npx -y @ghostpaw/souls skill prints the Agent Skill that ships in the package.
